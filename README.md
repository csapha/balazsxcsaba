# +1 Steal a Gem

Session-only Roblox MVP built with Rojo + Wally.

Mine the rock with your pickaxe, gems pop out, collect them, sell them for cash,
and upgrade your pickaxe for better luck. Stealing from other players' plots is
the next slice (see the roadmap).

## The idea

- **+1 incremental loop + "Steal a X" multiplayer meta combined** — no other
  Roblox game ships this exact loop yet.
- **Mine the rock** (`Workspace.Map.Mine.MineRock`) — stand close and
  click/tap with the pickaxe equipped. No aiming, no ProximityPrompts: the
  server validates distance + cooldown + "pickaxe is equipped".
- **7 rarity tiers**: Common, Uncommon, Rare, Epic, Legendary, Mythic, Secret
  (Kavics -> Csillagko). Odds and values live in `src/shared/Config/Ores.luau`.
  Only ores that have a real model (see `Templates/Gems`) can drop — the rest
  are skipped until their models are imported.
- **Collect** by walking over the gem — it flies to you (magnet), no prompts.
- **Pickaxe tiers** (Basic -> Stone -> Iron -> Gold -> Diamond -> Star) raise the
  luck multiplier (better odds for rarer gems) and hit speed.
- **Later**: player plots (tycoon), open tray (stealable) vs vault (safe),
  guards, Heist Hour, trading, zones, server announcements.

## Project layout

- `src/shared`
  - `Config/Game.luau` — global constants (cooldowns, limits, UI colors, flags)
  - `Config/Ores.luau` — ore definitions: odds, value, color, template
  - `Config/Pickaxes.luau` — pickaxe tiers: cost, luck, speed
  - `Format.luau` — number formatting, `Signal.luau`, `Net.luau` (remotes)
- `src/server`
  - `init.server.luau` — bootstrap
  - `Services/PlayerData.luau` — session state + mutations (persistence-ready)
  - `Services/ClientSync.luau` — leaderstats + data snapshot to clients
  - `Services/PickaxeService.luau` — gives the pickaxe Tool to the player
  - `Services/OreService.luau` — gem spawn / pickup / despawn
  - `Services/MiningService.luau` — hit validation, rarity roll
  - `Services/EconomyService.luau` — selling gems, buying pickaxes
- `src/client`
  - `init.client.luau` — bootstrap
  - `Controllers/MiningController.luau` — swing + sends the aim direction
  - `Controllers/EffectsController.luau` — particles, floating "+1"

There is **no HUD right now** — the current slice is intentionally just the
mining loop (hit rock -> gem pops out -> collect). Shop/Backpack/stats panels
come back later, together with the plot/steal systems.

## Studio hierarchy (authored, not generated by code)

```
Workspace
  Map
    Mine
      MineRock          -- the rock you mine
  Drops                 -- runtime-created; ore drops land here

ServerStorage
  Templates
    Pickaxes
      DefaultPickaxe    -- cloned into the player's Tool
    Gems
      Gem_Common        -- ore models cloned on each hit
      Gem_Amethyst ...  -- add the rest as they get imported
```

Lookup order (first hit wins):

- mine: `Workspace.Map.Mine.MineRock` (legacy fallback: `Workspace.MineRock`)
- pickaxe: `ServerStorage.Templates.Pickaxes.DefaultPickaxe` ->
  `ReplicatedStorage.Assets` -> `Workspace`
- gems: `ServerStorage.Templates.Gems` -> `ReplicatedStorage.Assets` ->
  `Workspace`

If a gem model is missing, a colored ball placeholder is used instead.

## Pickaxe swing animation

Out of the box the swing is a built-in procedural animation (shoulder + torso
tween, client-side). For a real animation:

1. Make or import one in Studio (Animation Editor) and **publish** it.
2. Put the id in `src/shared/Config/Game.luau`:

   ```lua
   SwingAnimationId = "rbxassetid://123456789",
   ```

The client then plays that animation instead (it replicates to other players).

Note: Creator Store "pickaxe swing" items are usually rigs / KeyframeSequences,
not published animations — they need to be published from the Animation Editor
first to get a usable asset id.

## Session-only

There is **no DataStore persistence yet** — `Game.Persistence = false`.
All progress resets when the server session ends. The state shape is kept clean
so the save/load layer can be enabled later with a single flag (the code paths
already exist in `PlayerData`).

The in-game UI text is English.

## Getting started

1. Open the Studio place and make sure the models above are in `Workspace`.
2. Start the Rojo server:

   ```bash
   rojo serve
   ```

3. Connect from the Rojo Studio plugin and press Play.

To validate the filesystem source tree without Studio:

```bash
rojo build -o "stealgame-build.rbxlx"
selene src
```
